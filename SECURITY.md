## Reporting a Vulnerability

We take the security of this project seriously. If you discover or suspect a security vulnerability, please **do not open a public issue or discussion thread**.

### Preferred Reporting Method
* Submit a report directly via **GitHub Private Vulnerability Reporting** under the **Security** tab of this repository (click **Report a vulnerability**).

### Alternative Contact Method
* If Private Vulnerability Reporting is unavailable or you prefer direct communication, please email your report to **wilooper@proton.me**.

---

## What to Include in Your Report

To help us evaluate and patch the issue quickly, please provide:
1. **Vulnerability Type:** (e.g., Cross-Site Scripting (XSS), SQL Injection, Authentication Bypass, Remote Code Execution, Secrets Leak).
2. **Impact:** Clear description of what an attacker could achieve.
3. **Reproduction Steps:** Step-by-step instructions or a Minimal Working Example (MWE) / Proof of Concept (PoC).
4. **Environment Context:** Operating system, language version, runtime parameters, or dependencies involved.

---

## What to Expect

* **Initial Acknowledgment:** We will confirm receipt of your report within **48 hours**.
* **Status Updates:** We will update you at least once every **5–7 days** on triage status, verification progress, and fix development.
* **Fix & Advisory:** Once a patch is developed and verified, we will issue a security release and a public GitHub Advisory.
* **Credit:** With your permission, we will credit your responsible disclosure in the security release notes.
