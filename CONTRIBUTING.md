# 🤝 Contributing to Lyrica

First off, thank you for considering contributing to **Lyrica**! It’s community members like you that make open-source software great.

Whether you're fixing a bug, updating documentation, or proposing a new feature, all contributions are welcome and appreciated.

---

## 📜 Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please read it to understand our community standards. Report any unacceptable behavior privately to **wilooper@proton.me**.

---

## 🛠️ How Can You Contribute?

### 1. Suggesting Ideas & Features
* Ideas and feature requests should be proposed in our **[GitHub Discussions](https://github.com/Wilooper/Lyrica/discussions)** tab under the **Ideas** category.
* Please search existing discussions and issues first to see if your idea has already been suggested.

### 2. Reporting Bugs
* Check the **[Issues](https://github.com/Wilooper/Lyrica/issues)** tab to see if the bug has already been reported.
* If it hasn't, open a new Issue providing a clear title, steps to reproduce the bug, expected vs. actual behavior, and relevant environment details.

### 3. Security Vulnerabilities
* **Do NOT open a public issue for security bugs.**
* Please follow our [Security Policy](SECURITY.md) to report vulnerabilities safely via GitHub Private Vulnerability Reporting or by emailing **wilooper@proton.me**.

---

## 🚀 Development & Git Workflow

Follow these steps to submit your code changes to Lyrica:

### Step 1: Fork the Repository
Click the **Fork** button at the top right of the [Lyrica Repository](https://github.com/Wilooper/Lyrica) page to create a copy under your own GitHub account.

### Step 2: Clone Your Fork
Clone your fork to your local machine and navigate into the project directory:

```bash
git clone [https://github.com/YOUR-USERNAME/Lyrica.git](https://github.com/YOUR-USERNAME/Lyrica.git)
cd Lyrica
```
## Step 3: Create a New Branch

Create a descriptive branch name for the work you're doing:

```bash
git checkout -b feature/amazing-feature
```

Use clear prefixes like:

- `feature/` for new functionality  
  Example: `feature/add-lyrics-translation`
- `fix/` for bug fixes  
  Example: `fix/api-fallback-timeout`
- `docs/` for documentation updates  
  Example: `docs/update-readme`

---

## Step 4: Make Your Changes & Format Code

### Python Code Style

Follow the **PEP 8** style guide for code cleanliness and readability.

### Documentation

Update relevant comments, docstrings, or `README.md` sections if your changes add or modify existing behavior.

---

## Step 5: Commit Your Changes

Write clear, concise, and descriptive commit messages:

```bash
git commit -m "feat: add amazing new feature"
```

Examples:

```bash
git commit -m "feat: add lyrics translation support"
git commit -m "fix: improve API fallback handling"
git commit -m "docs: update installation instructions"
```

---

## Step 6: Push to Your Fork

Push your local branch to GitHub:

```bash
git push origin feature/amazing-feature
```

---

## Step 7: Open a Pull Request (PR)

1. Go to the original **Wilooper/Lyrica** repository on GitHub.
2. Click **Pull Requests** → **New Pull Request**.
3. Select your branch from the dropdown menu.
4. Click **Create Pull Request**.
5. Provide a clear description of what your PR accomplishes.
6. Link any relevant open issues.

Example:

```text
Fixes #12
```

---

## ✅ Pull Request Checklist

Before submitting your PR, double-check that:

- [ ] Code follows the PEP 8 coding standards.
- [ ] Documentation has been updated for any new/changed features.
- [ ] Commit messages are clear and descriptive.
- [ ] Changes do not break existing functionality.
